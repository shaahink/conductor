# B3 — Safety, owner-gates & process control

**Stage goal:** remove finger-slip risk, add planned human approval gates, and give the operator
real control verbs (retry/rollback/pause-after-stage/budgets/approval).

**Sessions:** ~2. **Persona:** (default). **Depends on:** B2. **Branch:** `feat/baton-b3`.

## Why (findings)
- F-6: `A`/`K`/`S` fire on one keystroke; CLI verbs write control.json with no confirm.
- Shamshir needs a *planned* approval block (parity-pipeline P2.2 "nothing in P3+ ships until it's
  green"), not just break-driven NeedsHuman.

## Requirements
- R3.1 Destructive actions require confirmation in both TUI and CLI.
- R3.2 New owner-gate step type + `AwaitingOwner` status: a stage/checkpoint can block for approval
  even when green; resumable via approve from CLI/TUI (Telegram in B6).
- R3.3 Control verbs: `retry-stage`, `rollback` (reset working tree to a checkpoint commit),
  `pause-after-stage`, `goto <stage>`.
- R3.4 Per-run budget caps (`limits.maxRunCostUsd`, `limits.maxRunTokens`) that park the run at
  `AwaitingOwner`; approval mode that pauses before each commit/session.
- R3.5 Graceful Ctrl+C: final heartbeat REPORT.md + queue-resume + flush logs, then exit.

## Tasks → checkpoints
- **B3.1** — Confirm-gating. TUI: `A`/`K`/`S` open a confirm (second key or typed token); a
  simulated single keystroke must NOT act. CLI: destructive verbs require `--yes` or interactive
  confirm; `control.json` carries an intent stamp.
  - Gate: unit/headless test — finger-slip without confirm does not skip; confirmed path does.
- **B3.2** — Owner-gate step type. Plan can mark a stage/checkpoint `ownerGate: true`; reaching it
  green sets `AwaitingOwner` (emits `OwnerApprovalRequested`); `conductor approve <stage>` (and TUI
  key) emits `OwnerApprovalGranted` and continues.
  - Gate: state-machine test — owner-gate blocks on green, resumes on approve; persisted across restart.
- **B3.3** — `retry-stage`, `rollback`, `pause-after-stage`, `goto`. Rollback resets to the recorded
  checkpoint commit (safe: refuses if uncommitted work would be lost unless `--force`).
  - Gate: tests for each verb; rollback refuses on dirty tree without force.
- **B3.4** — Budget/token caps + approval mode; parks at `AwaitingOwner` with a clear reason.
  - Gate: a run exceeding a tiny cost cap parks (test with fake-agent reporting cost).
- **B3.5** — Graceful Ctrl+C path (final heartbeat + queue-resume + flush).
  - Gate: cancellation test — state saved, resume queued, log flushed, exit code correct.

## Definition of done
No destructive action without confirm; owner-gates + approval work end-to-end; control verbs + budget
caps land; Ctrl+C is clean. Full battery green.

## Traps
- Owner-gate must be a first-class projection off the event log (B2), not a bolt-on flag, so it
  survives restart and shows in timeline/report/Telegram.
- Rollback is destructive — gate it hard (dirty-tree refusal, explicit `--force`, log the reset).
