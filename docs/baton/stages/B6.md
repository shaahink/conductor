# B6 — AFK + two-way Telegram + richer REPORT.md

**Stage goal:** phone-grade AFK observability and control, a cleaner report that doesn't pollute
branch history, and the first real proof Conductor drives a non-Loom plan (Shamshir, headless).

**Sessions:** ~2. **Persona:** (default). **Depends on:** B2, B3 (owner-gate), B5.
**Branch:** `feat/baton-b6`.

## Why (findings)
- D-3: two-way Telegram. F-4: heartbeat commits pollute history.
- Acceptance milestone: Shamshir must be drivable headless by end of this stage.

## Requirements
- R6.1 Telegram client via long-poll `getUpdates` (no public endpoint; works behind NAT). Config:
  bot token + allowed chat id(s). Push on needs-human / owner-gate / complete / backoff; `/status`
  on demand (uses the same snapshot/StatusAgent context).
- R6.2 Two-way control: inline-keyboard `callback_query` → writes `control.json`
  (pause/resume/skip/inject/approve-owner-gate). Chat-id allowlist; destructive actions get a
  confirm button (mirrors B3).
- R6.3 Richer REPORT.md (progress bars, collapsible per-stage, commit links) + **clean heartbeat**:
  heartbeat updates go to a dedicated report ref/branch or amend the previous heartbeat commit, so
  the feature branch history stays clean.
- R6.4 Notify hooks (webhook/Discord/Slack) as first-class documented examples.
- R6.5 **Acceptance:** the stable driver runs Conductor against a fresh Shamshir iteration
  (parity-pipeline) and delivers **P-0 + P0.1** headless (land-the-tree + the ¼-sizing FakeTransport
  parity test — both non-credentialed), independently verified.

## Tasks → checkpoints
- **B6.1** — Telegram poll client + push notifications + `/status`. Runs as a hosted service (B2 host).
  - Gate: mock-Telegram server test — push delivered; `/status` returns a status message.
- **B6.2** — two-way control (inline keyboard → control.json) with allowlist + confirm.
  - Gate: mock round-trip — a button press produces the right control action; unauthorised chat id
    is rejected; destructive needs confirm.
- **B6.3** — richer REPORT.md + clean heartbeat.
  - Gate: heartbeat updates produce no new commits on the feature branch (verified by commit count
    over a simulated long session); report renders bars/collapsibles.
- **B6.4** — notify hooks examples.
  - Gate: a webhook notify fires on NeedsHuman (test with a local listener).
- **B6.5** — Shamshir P-0 + P0.1 headless acceptance.
  - Gate: session logs + gate outputs + tracker diff show P-0 and P0.1 delivered and independently
    verified; evidence committed under `docs/baton/audits/B6-shamshir-acceptance.md`.

## Definition of done
Two-way Telegram works from the phone; REPORT.md is rich and history-clean; Shamshir is drivable
headless (P-0 + P0.1 landed). Full battery green.

## Traps
- Telegram token is a secret — read from env/secret store, never commit it; the allowlist is
  mandatory (an open bot = anyone can pause/skip your run).
- The Shamshir acceptance must NOT touch the live DevContext2-ui run; use the Shamshir repo with its
  own `.conductor`. P0.1 is the FakeTransport parity test (no cTrader credentials).
