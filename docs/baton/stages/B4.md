# B4 — TUI overhaul (alt-screen + hierarchical tree + parsed panes)

**Stage goal:** make the dashboard feel like a real terminal app (alt-screen, clean restore),
restore the plan hierarchy, add severity, make the agent/thinking panes readable, and fix the
live-token lag.

**Sessions:** ~3. **Persona:** ui. **Depends on:** B2 (live token events). **Branch:** `feat/baton-b4`.

## Why (findings)
- The dashboard renders inline into scrollback (`AnsiConsole.Live … AutoClear(false)`), which is why
  it doesn't feel like a native app and why headers historically stacked.
- F-5: sub-plan tree regressed — you can't see L3 ▸ L3.1 done / L3.2 active in one place.
- F-3: token line lags a whole session while cost is live.
- Live UX pains: destructive keys inline (handled in B3), tool-call sprawl buries the narrative,
  "3 untracked" is cryptic.

## Requirements
- R4.1 Alternate-screen buffer (`\e[?1049h` on start, `\e[?1049l` + cursor restore on exit/crash);
  the prompt returns clean; no scrollback pollution.
- R4.2 Rebuild `DashboardRenderer.BuildRoot` on Spectre `Layout`/`Grid`/`Panel`/`Rule` (retire the
  scattered manual composition).
- R4.3 Hierarchical plan tree: stages with expandable sub-checkpoints; per-stage columns (done,
  attempts, last outcome, cost); collapse/expand; filter (todo/active/failed) + search for large plans.
- R4.4 Severity model (INFO/WARN/ERROR/SUCCESS/WAITING/HUMAN) applied to log + status; header labels
  clarified ("3 untracked" explained or dropped when irrelevant).
- R4.5 Structured thinking pane (Goal / Hypothesis / Evidence / Action parsed from reasoning) +
  agent stream grouped by tool-call with foldable long output (command name + short arg digest,
  expand on demand).
- R4.6 Command history search + filters (`/build`, `/git`, `/test`; filter commands/thoughts/errors).
- R4.7 Live-consistent token line (folds `TokenDelta` from B2 so tokens and cost agree); select a
  stage/checkpoint row → open its doc section (DocsExtractor exists).

## Tasks → checkpoints
- **B4.1** — alt-screen enter/leave with guaranteed restore (try/finally + `AppDomain.ProcessExit` /
  `PosixSignalRegistration` for Ctrl+C). Fallback to inline when output is redirected.
  - Gate: manual + a headless test that the enter/leave sequences are emitted; `preview` still works
    redirected.
- **B4.2** — Spectre `Layout` rebuild; keep the pure `DashboardState → IRenderable` split (testable).
  - Gate: `DashboardRendererTests` pass against the new layout; no header stacking at small heights.
- **B4.3** — hierarchical tree (uses B10 hierarchical stages if present, else derives from checkpoint
  ids) + filter/search.
  - Gate: headless renderer test shows sub-checkpoints + per-stage columns; filter narrows rows.
- **B4.4** — severity model + header label fixes.
  - Gate: renderer test asserts severity colour/glyph mapping; "untracked" label reworded.
- **B4.5** — structured thinking parse + tool-call folding.
  - Gate: given a captured reasoning/agent stream, the pane groups tools and extracts Goal/Action
    (unit-tested on a fixture).
- **B4.6** — command history search + filters.
  - Gate: filter test over a synthetic history.
- **B4.7** — live-consistent token line + doc-on-select.
  - Gate: snapshot with a running session shows tokens including the live delta; selecting a stage
    opens its doc section.

## Definition of done
Alt-screen with clean restore; Spectre-Layout dashboard; hierarchical tree with filters; severity;
readable thinking/agent panes; live-consistent tokens; doc-on-select. Full battery green.

## Traps
- Alt-screen + Spectre `Live` interaction is the risk: ensure restore on EVERY exit path (normal,
  exception, Ctrl+C, redirected output). A missed `\e[?1049l` leaves the user's terminal wedged.
- Keep rendering pure and unit-testable (the current `DashboardState`/`DashboardRenderer` split is
  good — preserve it).
