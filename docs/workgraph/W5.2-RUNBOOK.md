# W5.2 — runbook for the real-model proof run

**One command:**

```powershell
powershell -ExecutionPolicy Bypass -File tools/w5/start-w52.ps1
```

That is the whole thing. Everything below is why, and what to do when it ends.

## What this run is actually testing

Not the model. **The engine.** W5.1 already proved the loop end to end against a token-free agent —
one process, a markdown document in, `RunFinished` out. W5.2 asks the only question that rehearsal
could not: does it still hold when the agent is a real model that thinks, wanders, misreads things
and occasionally does something surprising?

So the work is deliberately small and mechanical — four followup rows open since the B/F-series
audits, re-verified as still-real in the 2026-07-28 triage, each independently gated by the full
battery. Real enough that gates can genuinely fail; small enough that finishing says something
about the loop rather than about the model.

**Passing** (`docs/CONDUCTOR-WORKGRAPH.md:180`): started once → `RunFinished`, budget cap set,
watchdog armed but idle, **zero interventions**. If you rescue it, it did not pass. Stop it, fix
what bled, start again — that is the brief's *"fix what bleeds; re-run until clean"*, and the
expectation is more than one attempt.

## What the command does before it spends anything

1. **Refuses a dirty working tree.** An unattended run commits what it finds; afterwards you cannot
   tell its work from yours.
2. **Puts the run on its own branch** (`w52-proof`, created from HEAD). Never `feat/foreman` — a
   real model committing unattended to the branch about to merge into `master` is the one outcome
   with no cheap undo. `HookConfig` is best-effort by contract (a nonzero exit never blocks a run),
   so this could not be enforced by a plan hook; making it one command was the alternative to
   making it a step you have to remember.
3. **Publishes the branch.** The session prompt instructs the agent to push, and a push with no
   upstream fails — which reads to an agent as a problem worth solving, and burns tokens on it.
   `-NoRemote` skips this if you would rather nothing touched the remote.
4. **Builds the engine, runs `doctor`, stops on any failure.** Watch the auth line: a dead
   credential is the most common way an overnight run becomes an empty log — the whole reason W3.2
   exists. `claude setup-token` if it complains.
5. **Prints what it may spend and asks once.**

## While it runs

Leave it alone. Leave the window open — since W3.3, closing it parks the run cleanly rather than
severing it, but **parked is not finished**, and this run needs to finish on its own. Use
`-Headless` if you want to close the terminal; it appends to `.conductor/w52-run.log`.

The rails are armed and *expected to stay idle*. If one fires, that is data, not a fault:

| Rail | Fires when | What it means for the proof |
|---|---|---|
| `maxRunCostUsd: 25` | total spend hits the cap | Parks at AwaitingOwner. Did not overrun — the cap worked. Read where the money went before raising it. |
| `maxSessions: 24` | 24 sessions elapse | Parks at a session boundary. Four checkpoints should not need 24 sessions; if it gets here, something is churning. |
| session timeout 45m | one session runs too long | W3.1's watchdog on its own thread. Bug #8 was a 90-minute limit that fired at 337 — if that recurs, the watchdog regressed. |
| stall 12m (+3m grace) | agent silent, no tool calls, no bg children | Before W3.1 this rail had **never fired in any run ever logged**. Its first real firing is worth reading closely. |
| auth preflight | credential dead at start | Parks naming its own fix, before spending anything. |
| circuit breaker | two identical failures in a row | Consults the advisor instead of queuing another identical retry. |

Anything that parks leaves the run resumable. Nothing here loses work.

## Two things this run is specifically probing

Both are known gaps carried out of W5.1 rather than fixed blind, and both only bite with a real model:

- **The prompt never names the checkpoint the engine will judge the session against.** It names the
  stage and says "read the tracker", so the agent re-derives by parsing markdown what
  `assignment.Items` already knows — and a disagreement is silent. *Mitigated here on purpose:*
  every stage's `notes` opens with `Deliver V1.1 = …`, so the checkpoint is named in the prompt
  after all. If this run goes clean, that mitigation is part of why, and the underlying gap is
  still worth closing properly.
- **`FU-OWNER-9` — an agent killing its own parent conductor.** It happened once, to a real model,
  when a build error named a pid it decided was a stale orphan. Nothing on the agent's side of the
  tool contract stops it. This is the first unattended real-model run since, and the prompt now
  explicitly tells the agent never to kill processes by name.

## When it ends

**Finished (`RunFinished`, exit 0).** That is the checkpoint. Hand it back for the audit —
`docs/workgraph/W5-AUDIT.md`, mapping the five owner acceptance criteria onto run.db and log
evidence. The evidence is already on disk; writing it up needs no further spend:

```powershell
conductor report -p plans/conductor-w52.plan.json --query "SELECT number, kind, stage_id, outcome, newly_done, cost_usd FROM sessions ORDER BY number"
conductor report -p plans/conductor-w52.plan.json --query "SELECT type, payload FROM events WHERE type = 'RunFinished'"
```

Remember `events.type` holds the CLR name (`RunFinished`), not the JSON discriminator
(`runFinished`) — the wrong one returns "no rows" and reads exactly like a defect.

**Parked.** Read `conductor status -p plans/conductor-w52.plan.json` and the tail of
`.conductor/conductor.log`. Do not nudge it and continue — that forfeits the run. Note what
happened, stop it, fix it, start again.

**Then:** the four followup rows it closed get marked in `.conductor/followups.md`, W5.2 goes DONE
in `CONDUCTOR-WORKGRAPH.md`, and the merge of `feat/foreman` → `master` is unblocked — the branch's
own work first, then `w52-proof` on top of it.

## Undo

Nothing here is hard to reverse. The run lives entirely on `w52-proof`:

```powershell
git checkout feat/foreman
git branch -D w52-proof
git push origin --delete w52-proof   # only if it was published
```
