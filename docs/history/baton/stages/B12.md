# B12 — Controlled parallelism

**Stage goal:** run work concurrently WITHOUT weakening the trust model — read-only analysis lanes
first, then isolated-worktree mutating lanes behind a full-battery merge gate. Last by design.

**Sessions:** ~3. **Persona:** architect. **Depends on:** B2, B7, B8, B9. **Branch:** `feat/baton-b12`.

## Why
- The brain (B8/B9) can schedule design/QA/architecture/research in parallel, and blend-in fixes for
  handover debt (B8 followups) — but parallelism is the one feature that can undermine
  "never trust the agent." The design confines the new verification surface to a **merge gate**.

## Requirements
- R12.1 Tier A — read-only analysis lanes: arch review, design proposals, QA of committed work,
  research. Run like `StatusAgent` (read-only by construction, scratch cwd). Never touch the working
  tree → no git contention, no merge gate. Outputs are artifacts that feed the next prompt + handover.
- R12.2 Worker pool + concurrency cap + brain scheduling; opt-in per task-type; events for lane
  lifecycle (`LaneStarted/LaneFinished`).
- R12.3 Tier B — isolated-worktree mutating lanes: a delivery/fix task runs in its own `git worktree`
  on a scratch branch; a **merge gate** runs the FULL battery on the integrated tree before the
  lane's work is accepted; conflicts/red battery → the lane is rejected and reported, never merged.
- R12.4 fix-lanes consume `.conductor/followups.md` (blend-in debt fixing) as Tier-B lanes.

## Tasks → checkpoints
- **B12.1** — Tier A read-only lanes + artifact wiring.
  - Gate: a read-only arch/QA lane runs concurrently with the main session, produces an artifact, and
    that artifact is injected into the next prompt (test); it provably never writes the working tree.
- **B12.2** — worker pool + concurrency cap + scheduling + lane events.
  - Gate: N lanes respect the cap; lane lifecycle events recorded (test).
- **B12.3** — Tier B isolated-worktree lanes + merge gate.
  - Gate: a mutating lane in a worktree is merged ONLY when the full battery is green on the merged
    tree; a red-battery lane is rejected and reported (test with fake-agent producing good/bad diffs).
- **B12.4** — fix-lanes from followups.
  - Gate: a followup entry spawns a Tier-B fix-lane whose result is merge-gated (test).

## Definition of done
Read-only lanes in production; isolated-worktree mutation behind a full-battery merge gate; fix-lanes
blend in handover debt. The trust model holds: no lane mutation is ever accepted without the merge
gate. Full battery green.

## Traps
- **This is the highest-risk stage.** Ship Tier A fully before Tier B. A Tier-B lane must NEVER write
  the primary worktree directly — only its own `git worktree`, merged behind the gate.
- Merge conflicts are expected; the policy is reject-and-report, not force-merge. The main sequential
  loop remains the backbone; lanes are additive.
- Concurrency cap must be conservative (git/index and build-server contention). Default low.
