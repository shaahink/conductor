# B10 — Advanced orchestration

**Stage goal:** smarter scheduling (dependency graph), first-class hierarchical stages, per-stage
hooks, and collapsing the duplicated gate battery for token/time savings. (Session branching is
deferred — D-6.)

**Sessions:** ~2. **Persona:** (default). **Depends on:** B2. **Branch:** `feat/baton-b10`.

## Why
- Plans have real dependencies (Shamshir P0→P1→P2 strict; P3 after P2.2). Hierarchical stages make
  the tree (B4) and reports honest. The agent's own ritual battery + Conductor's re-run duplicate
  work (RESEARCH.md rec #2).

## Requirements
- R10.1 `stages[].dependsOn: [ids]` → ready-stage ordering (execution stays sequential for safety;
  ordering just picks the next *ready* stage).
- R10.2 First-class hierarchical stages (parent/child) in state + reports + the B4 tree.
- R10.3 Per-stage pre/post hooks (beyond the global setup/teardown).
- R10.4 Collapse the double gate battery: one source of truth (the agent either defers to Conductor's
  battery or Conductor trusts a signed ritual result it re-checks cheaply) — measure the token/time drop.

## Tasks → checkpoints
- **B10.1** — `dependsOn` + ready-stage selection.
  - Gate: a plan with deps runs stages in a valid topological order (test); a cycle fails validation.
- **B10.2** — hierarchical stages in model/state/report/tree.
  - Gate: parent/child render in the tree and report (test).
- **B10.3** — per-stage hooks.
  - Gate: a stage hook runs before/after its sessions (test).
- **B10.4** — collapse double battery + measurement.
  - Gate: token-per-checkpoint measured before/after on a self-run; documented drop; correctness
    preserved (full battery still the arbiter).

## Definition of done
Dependency-ordered, hierarchical, hook-capable orchestration with a single gate source of truth and a
measured efficiency gain. Full battery green.

## Traps
- Sequential execution is preserved (no parallel mutation here — that's B12). `dependsOn` only affects
  ordering/readiness.
- Collapsing the battery must NOT weaken verification: if Conductor trusts a ritual result it must
  still cheaply re-verify (HEAD-sha + a fast check), never take the agent's word (trust model).
