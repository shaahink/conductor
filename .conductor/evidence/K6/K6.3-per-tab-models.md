## The line the refactor draws, and why it is where it is

A message moves to the tab **when the state it lands has exactly one reader**. Measured, not assumed
— `grep -l "data\.<field>"` for each shared slice:

- `data.Processes` → `tab_processes.go` only → `MsgProcessesUpdated`/`MsgProcessKilled` move.
- `data.Ledger` / `data.Bugs` / `data.Evidence` → `tab_knowledge.go` only → both knowledge messages move.
- `data.Sessions` → `tab_history.go` **and** `tab_report.go` → `MsgSessionsUpdated` stays in the shell.
- `data.Tasks` → `tab_kanban.go`, `tab_agent.go` and the sidebar → `MsgTasksUpdated` stays in the shell.

What is left in the root `Update` is the shell: sizing, keys, ticks, the five stream messages, the
two multi-reader polls, and the two cross-cutting results (`MsgControlSent`, `MsgInjectSent`) that
touch a tab's status line as a *side effect* of a global action. Agent is deliberately absent from
`tabUpdaters` rather than given an empty handler — its two bodies are fed by streams whose channels
the shell owns.

## The help card cannot lie any more

The Tabs grid was three hand-typed rows and the folded row a hand-typed sentence, beside a comment
admitting the hazard. Both now render from `tabKey`/`tabNames` and `foldedTabs`, the same idiom this
file already used for `verbGroupLegend` (from `allVerbs`) and `themeLegend` (from the theme
registry). `foldedTabKey`, the router's lookup, is **built from** `foldedTabs` (`model.go:84-93`), so
the alias table has one source instead of a map beside a sentence.

`TestHelpLegendFollowsARebind` (`help_size_test.go:81`) is the claim that matters: rebind Knowledge
to `Z`, fold a surface onto `y`, render the card — and the card follows with no second edit. Against
the old hand-typed legend that test fails on both assertions.

## The frames — driven, not asserted

`K6.3-frames.txt` was produced by driving the real model: `tui.New` over `api.NewDemoSource()` (the
source `conductor-face --demo` uses), a real `tea.KeyPressMsg` per keypress, **the real `tea.Cmd`
that keypress returns executed and its message fed back through `Update`**, and the real `View()`.
Nothing test-only is involved — no `newGoldenModel`, no `fakeSource`. The harness was a throwaway
`cmd/k63frames` deleted after the capture.

| frame | what it proves |
|---|---|
| 1 | Home renders off the shell's own state poll |
| 2 | `k` → `cmdFetchKnowledge` → `MsgKnowledgeUpdated` **routed by `updateKnowledge`** — the ledger body is populated |
| 3 | `r` then `G` → the footer reads `↑↓ d/u G/home scroll 100%`: `reportModel.vp` still lands on the end |
| 4 | `p` → `MsgPlanLoaded` **routed by `updatePlan`** into `m.plan.doc` — the stage list is populated |
| 5 | `b` + `MsgTaskWritten{add}` → the board's status line reads `✓ add`, written by `updateKanban` |
| 6 | `g` + `MsgTelegramTested` → `✓ sent — @conductor_bot delivered through the run's own push queue`, written by `updateTelegram` |
| 7 | the help card, Tabs grid and folded row derived |

Frames 5 and 6 are the ones that matter for the dispatch: those two messages reach the pane **only**
through `tabUpdaters` — the root `Update` has no arm for either any more — so a status line that
says `✓ add` is the dispatch working end to end, in a rendered frame, not in an assertion.

## What is deliberately left

- `plan.go` is still 1,085 lines. The spec offered it as "the next candidate … if the goldens stay
  green"; its *state* moved (22 fields into `planModel`) but its renderer did not split. That is a
  separate cut and it is named here rather than half-done.
- The tab models are structs with an `updateXxx`, not `tea.Model` implementations. A real
  `tea.Model` per tab needs `View()` to be parameterless, and every renderer here takes the shell's
  width, theme and shared `AppState` — the ADR (decision 3) asks for one focusable body per tab and
  a plain focus int, which is what this shape gives, without inventing a context object the Face has
  no other use for.
- `MsgControlSent` and `MsgInjectSent` still write a tab's status line from the shell. They are
  results of *global* verbs (a run control, an injection) that happen to be visible on a pane; moving
  them into a tab would put the global toast in the wrong file.
