## 1. The measurement — the owner's "can't read long text" is a runaway offset

This is the part the ADR is built on, and it was measured, not inferred from source reading.

`m.reportScroll++` (`face-go/internal/tui/tab_report.go:46`) has **no clamp in `Update`**. The only
clamp is a *local copy inside the renderer* — `scroll := min(m.reportScroll, maxScroll)` at
`tab_report.go:83` — which is never written back, and `View` has a value receiver so it cannot be.
The model's offset therefore grows without bound while the pane sits pinned at the bottom.

A temporary probe (`internal/tui/k61_probe_test.go`, run once and deleted; source reproduced in §4)
drove the real model. Verbatim output of `go test ./internal/tui/ -run TestK61Probe -v`:

```
=== RUN   TestK61ProbeScrollOffsetRunaway
REPORT: body stops changing at scroll offset 12; after 400 `down` presses m.reportScroll = 400
REPORT: 389 `up` presses were needed before the frame moved one line
KNOWLEDGE: key "pgdown" knowledgeScroll 0 -> 0
KNOWLEDGE: key "end"    knowledgeScroll 0 -> 0
KNOWLEDGE: key "home"   knowledgeScroll 0 -> 0
KNOWLEDGE: key "pgup"   knowledgeScroll 0 -> 0
KNOWLEDGE: key "k"      knowledgeScroll -> 0 (k is the Knowledge tab mnemonic)
--- PASS: TestK61ProbeScrollOffsetRunaway (0.27s)
PASS
ok  	conductor-face-go/internal/tui	1.944s
```

Two seconds on the arrow key past the end of a document freezes the Report pane for the next **389
keystrokes**, which is indistinguishable from a broken UI. On Knowledge, `pgup`, `pgdown`, `home` and
`end` are all no-ops — every one of them left the offset at 0 — and `k` never arrives at the pane at
all, because the mnemonic loop at `update.go:608` opens the Knowledge tab first.

Filed as **bug #30**. K6.2 closes it by construction: `viewport` clamps inside its own `Update` and
owns `YOffset` itself.

`charm.land/bubbles/v2 v2.1.1` — the `charm.land` path matching `charm.land/bubbletea/v2 v2.0.8`
already in `face-go/go.mod`, and the same module soft-serve imports. `face-go/go.mod` requires
bubbletea v2, lipgloss v2, glamour, harmonica and `x/term`; **`bubbles` appears nowhere in it**, which
is why all of the above is hand-rolled.

Probe source, for reproduction (created, run, and deleted this session):

```go
func TestK61ProbeScrollOffsetRunaway(t *testing.T) {
	m := newGoldenModel(120, 30).(Model)
	body, _ := m.renderReportPane()
	at0 := body
	bottomAt, prev, mm := -1, at0, m
	for i := 1; i <= 400; i++ {
		next, _ := mm.handleReportKey("down")
		mm = next.(Model)
		b, _ := mm.renderReportPane()
		if b == prev && bottomAt < 0 { bottomAt = i - 1 }
		prev = b
	}
	fmt.Printf("REPORT: body stops changing at scroll offset %d; after 400 `down` presses m.reportScroll = %d\n", bottomAt, mm.reportScroll)
	atBottom, ups := prev, 0
	for i := 1; i <= 500; i++ {
		next, _ := mm.handleReportKey("up")
		mm = next.(Model)
		b, _ := mm.renderReportPane()
		ups = i
		if b != atBottom { break }
	}
	fmt.Printf("REPORT: %d `up` presses were needed before the frame moved one line\n", ups)
	k := newGoldenModel(120, 30).(Model)
	for _, key := range []string{"pgdown", "end", "home", "pgup"} {
		before := k.knowledgeScroll
		next, _ := k.handleKnowledgeKey(key)
		k = next.(Model)
		fmt.Printf("KNOWLEDGE: key %-8q knowledgeScroll %d -> %d\n", key, before, k.knowledgeScroll)
	}
}
```
