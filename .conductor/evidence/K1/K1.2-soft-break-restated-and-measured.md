# K1.2 — the soft break is re-stated until it is obeyed, carries the remaining budget, and is measured

**Checkpoint:** K1.2 · **Branch:** `feat/karvan` · **Date:** 2026-08-04

## The defect

Measured across the Sarban face run's 33 post-cap sessions: **11 rollovers, all 11 ending at
8.00–8.13M tokens — the hard ceiling. Not one stopped at the 6.0M nudge.** Three reasons, all in the
code:

1. **Announced once.** `HookBudgetCommand` wrote `soft-break.delivered` on its first delivery and
   returned silently forever after. A paragraph delivered once, hundreds of thousands of tokens
   before the end, is read by an agent deep in a task and forgotten.
2. **It named the fact of a limit, not the budget.** `Notice` was a `const string`: "This session has
   used most of the tokens allotted to it." Nothing an agent could pace against.
3. **Nothing recorded whether it worked.** The only trace was `SoftBreakRequested` — that the engine
   raised it, never that the agent heard it. The tuning pass had to infer the conversion rate from
   outcome columns.

## The change

New `src/Conductor/Core/SoftBreak.cs` holds the rail: the two file payloads, the re-statement rule
and the notice text, shared by the engine that raises it and the hook that delivers it.

| Piece | Where | What |
|---|---|---|
| `SoftBreak.Signal` | `Core/SoftBreak.cs` | `.conductor/soft-break` is now JSON: spent, ceiling, threshold, the checkpoint in hand. An unparseable file (older engine) reads as "no numbers" and still wraps the agent up. |
| `SoftBreak.ShouldRestate` | `Core/SoftBreak.cs` | Pure rule: first delivery always; then a 3-minute interval **or** a token step, whichever comes first. |
| `SoftBreak.RestateTokenStep` | `Core/SoftBreak.cs` | `(ceiling - threshold) / 20` — scales with the plan. This era's 32M/22.4M gives 480k, i.e. ~20 restatements across the tail at a couple of hundred tokens each. |
| `CheckSoftBreak` | `Orchestration/SessionRunner.Mcp.cs` | Re-**writes** the signal every `RestateTokenStep` of spend, so each restatement quotes a live number. The event and both log lines still fire on the crossing only. |
| `HookBudgetCommand` | `Commands/HookBudgetCommand.cs` | No `const Notice`. Reads the signal, asks `ShouldRestate`, records the delivery, prints `SoftBreak.Notice(signal, n)`. |
| `SoftBreak.Notice` | `Core/SoftBreak.cs` | Quotes remaining/ceiling/percent, numbers the restatement, names the checkpoint in hand, and states the order **CLAIM FIRST → THEN THE HANDOFF → THEN COMMIT AND PUSH → SESSION-RESULT**, with the reason: the claim is what survives being cut off mid-sentence. |
| `SessionRecord.SoftBreak` + `sessions.soft_break` (migration v10) | `Models/SessionRecord.cs`, `Migrations/v10_session_soft_break.sql` | The measurement: threshold, ceiling, delivered count, first/last delivery time and token mark, and `obeyed`. NULL means "no ceiling, or never crossed" — deliberately not an empty object, so "nudged and ignored" and "never nudged" cannot be confused. |

`Obeyed` = the notice was delivered **and** the session ended without the engine's hard stop **and**
under its ceiling. Eleven of eleven would have been `false`.

## Proof

**`tests/Conductor.Tests/K1_2SoftBreakTests.cs` — `K1_2SoftBreakRuleTests`** (unit): the step scales
with the margin and is never zero; the first notice always goes out; a restatement waits for a token
step; a slow session is still re-nudged on the clock; the notice carries remaining/ceiling/percent,
the checkpoint and the ordered wrap-up with `CLAIM FIRST` before `THEN THE HANDOFF`; a restatement
says it is one; a signal with no numbers still wraps the agent up.

**`K1_2SoftBreakLiveTests`** (live, `Category=Integration`): a scratch repo with its own state dir,
this build's orchestrator, a **1000-token ceiling nudged at 0.5**. The stand-in agent spends 100
tokens a step and, after each step, runs the **real `conductor hook-budget --state-dir …`** from the
freshly-built exe — exactly the command the engine writes into the agent's PostToolUse settings.
When the notice has arrived twice it takes it, prints `SESSION-RESULT:` and exits.

Asserted: ≥2 notices (re-stated); notice 2 says so; both quote a remaining budget and the **second is
strictly smaller than the first** (the signal was refreshed, not repeated); the first fired at ≤500
tokens remaining (not before the threshold); the notice names `H0.1`, the checkpoint in hand; the
session did **not** roll over and finished under its ceiling; `rec.SoftBreak` reads
delivered/restated/**obeyed** with `LastAtTokens > FirstAtTokens`; and `sessions.soft_break` in
`run.db` carries the same JSON with `"obeyed": true`.

**`BudgetRailTests.HookBudget_IsSilentBetweenStatements_ButSpeaksAgainAsTheBudgetDrains`** replaces
`HookBudget_SpeaksOncePerSession`, which asserted the behaviour this checkpoint exists to overturn.
It keeps the half that is still true — no nagging on every tool call — and adds the half that was
missing: after another 100 of a 500-token margin, the hook speaks again and quotes `400 tokens`.

`RunDbTests.Schema_version_is_ten` follows the v10 migration.
