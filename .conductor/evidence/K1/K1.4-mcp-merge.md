# K1.4 — the MCP config merges the operator's servers instead of replacing them

**Claim.** A spawned session sees conductor's task tools **and** the MCP servers the operator has
already configured on the machine. The merge is proved against a repo that *already had* servers in it,
by a live orchestrator run, reading the file the child was actually handed. The prompt-side
deferred-tool fallback is untouched and now pinned by a second test.

## What was true before

`SessionRunner.Mcp.cs` `WireMcpServer` built both dialects from a literal one-entry map:

```csharp
mcpServers = new Dictionary<string, object> { ["conductor-tasks"] = ... }   // and nothing else, ever
```

and `McpArgsFor` appended `--strict-mcp-config`, whose comment stated the intent outright: *"the session
gets exactly the conductor server and nothing the developer happens to have in `~/.claude.json`"*. So the
field report in `docs/dev/FIELD-NOTES-2026-07-29-devcontext.md` §8 — a user-scope chrome-devtools server
invisible to every spawned session — was not a bug in the wiring, it was the wiring working as written.

## What is true now

- `src/Conductor/Core/Integrations/OperatorMcpServers.cs` (new) reads the operator's configs:
  - **claude dialect** (`mcpServers`): `~/.claude.json` user scope → `<repo>/.mcp.json` project scope →
    `~/.claude.json` `projects[<repo>].mcpServers` local scope, later scope winning a name collision,
    which is the CLI's own precedence. The project key is matched across separator and case differences,
    because plans in this repo carry forward slashes and the CLI writes the key as it saw it.
  - **opencode dialect** (`mcp`): `~/.config/opencode/opencode.json`/`.jsonc` → the repo's own, repo wins.
    JSONC comments and trailing commas are accepted, because operators write them.
- `SessionRunner.Mcp.cs` `InheritOperatorMcpServersAsync` folds the result in beside `conductor-tasks`,
  which is written first and cannot be displaced: `OperatorMcpServers` drops an operator entry named
  `conductor-tasks` outright, because handing that name away points the claim path at another process
  and the run then looks like it simply never claimed anything.
- Failure is inert. A missing config is silent; an unreadable, oversized (>8MB), malformed or
  wrong-shaped one is skipped with a note in the session log and the other scopes still merge. A typo in
  one person's home directory must not stop every session on the machine.
- `--strict-mcp-config` **stays**. It used to buy exclusion; it now buys determinism — one file decides
  what the child loads, and the session log names every source that went into it.
- Opt-out: `agent.inheritMcpServers: false` (documented in `docs/plan-config.md`). Conductor's own
  server is wired either way.

## Live proof — a real run, a repo that already had servers

`K1_4McpMergeTests.LiveSession_GetsConductorsToolsAndTheOperatorsServers` builds a scratch git repo
under `%TEMP%`, plants `.mcp.json` and `opencode.json` in it *before* conductor writes anything, and
runs the real `Orchestrator` with a claude-shaped fake agent that copies both configs out of
`.conductor/` before the engine deletes them at session end.

Engine log from that run (`.conductor/bg-logs/dotnet-20260804-234607374.log`):

```
[00:46:37] K1.4: claude config inherits 1 operator MCP server(s) [chrome-devtools]
           from C:\Users\shahi\.claude.json (1), <scratch-repo>\.mcp.json (1)
[00:46:37] K1.4: opencode config inherits 6 operator MCP server(s)
           [cloudflare, cloudflare-docs, cloudflare-bindings, cloudflare-builds,
            cloudflare-observability, operators-own]
           from C:\Users\shahi\.config\opencode\opencode.jsonc (5), <scratch-repo>\opencode.json (1)
```

Two things worth reading twice. The claude line names **`chrome-devtools`** — the exact server the field
report said was invisible — and it was found in the *real* `~/.claude.json` on this machine as well as in
the scratch repo. The opencode line picked up five real servers from this machine's global config that
no session had ever been able to see. Neither was fixture: both are what the operator actually has.

The test then reads the copied `mcp-config.claude.json` and asserts `conductor-tasks` is present with
this run's `--run-id`, that `chrome-devtools` came through verbatim (`npx chrome-devtools-mcp@latest`),
that the opencode config carries both `conductor-tasks` and `operators-own`, and that
`--strict-mcp-config` is still on the child's argv. The same test runs a second time with
`inheritMcpServers: false` and asserts the config holds **exactly** `["conductor-tasks"]` in both
dialects — on this machine, with all of the above configured. The opt-out really opts out.

## The prompt-side fallback stays

`src/Conductor/Core/ToolContract.cs:63` is unchanged — the line that tells an agent to `ToolSearch` for
`task_update` when the harness defers conductor's tools, and names the CLI that works regardless. It was
already pinned by `SF6_1TemplateLessonsTests.DeferredToolsNoteCarriesTheCliFallbackOnTheSameLine`; K1.4
adds a second pin in `SF7_1DocsMatchRealityTests.Backlog.cs` so deleting it also fails the backlog gate.
A deferred tool is the harness's choice and conductor cannot assert otherwise.

## A test that turned over rather than being deleted

`SF7_1DocsMatchRealityTests.TheFiledMcpItemStillDescribesWhatWireMcpServerActuallyWrites` existed to pin
the premise of the filed backlog item — *the written config names exactly one server* — and its own
doc-comment said the entry goes stale the moment `WireMcpServer` learns to merge. It has. The test was
rewritten in place (`TheFiledMcpItemRecordsTheMergeThatShippedAndTheHalfThatDidNot`) to pin the state
that replaced it: the merge is real, `docs/dev/NEXT-FEATURES.md` records it as shipped, and the harness
half is still open for the stated reason. `OperatorMcpServers` was added to `ShippedFeatures`, so the
page and the tree cannot drift apart again.

## One note for whoever touches this next

`WireMcpServer` is now `WireMcpServerAsync`. That was not taste: reading a file with `File.ReadAllText`
trips MA0045, and the only alternative to real async I/O was a `#pragma warning disable`, which is
impossible here — `src/` sits at exactly 38 suppressions and `tools/gates/ratchet-baseline.json` caps it
at 38. The rule pushed the code to the better shape.

Filed on the way past: **bug #24** — `AgentConfig.Merge` never assigns `Env`, so a stage-level agent
override silently wipes plan-level `agent.env` (e.g. `OPENCODE_CONFIG`). Not touched here; K1.4 owns the
MCP config, not the merge semantics of a neighbouring field.
