## What the code did before, measured

`.conductor/.gitignore` is `*` with four exceptions (`.gitignore`, `REPORT.md`, `followups.md`,

`StateDir` keeps its meaning: per-run scratch (`logs/`, `sessions/`, transcripts, evidence), the
discovery files a live run publishes (`control-plane.json`, the engine lock) and the tracked
deliverables (`REPORT.md`, `followups.md`, `handovers/`). Only `run.db` moved, which is why fleet
discovery, `ps` and `watch` needed no change — `FleetScan`/`FaceTarget`/`PsCommand` never touched
the database, only `.conductor`.

Resolution precedence, `StateHome.Resolve`:

1. `CONDUCTOR_RUN_DB` — this exact file, no derivation.
2. `<repo>/.conductor/state-pointer.json` — how a second working tree points at the primary tree's
   run. This is the lanes prerequisite.
3. Derived: `<CONDUCTOR_STATE_HOME | %LOCALAPPDATA%/conductor | $XDG_DATA_HOME/conductor>/runs/<slug>/run.db`,
   slug = `<repo-leaf>-<plan>-<8 hex of SHA-256 over normalised repo path + NUL + plan>`.

Only case 3 imports or catalogues. The import **copies** and leaves the original: an older engine
may still be installed on this machine (one of them is driving this run), and renaming its database
out from under it would hand it an empty store.

database after the rig was gone. It now writes only when the resolution was `Derived`.

## Two things this change surfaced rather than caused

1. **K2.2's store-does-not-print boundary caught the migration's stderr line.**
   `ArchitectureBoundaryTests.TheStoreDoesNotWriteToTheConsole` failed the moment
   `StateMigration` called `Console.Error`. The notice now goes through
   `StateMigration.Announce`, a sink `Program.cs` installs; Core stays free of `Console`.

2. **149 test cleanups were silently not running.** They called
   `Directory.Delete(repo, recursive: true)` and caught only `IOException` — and that `IOException`
   was the engine holding `.conductor/run.db` open. `.conductor` sorts before `.git`, so the delete
   threw there and stopped, never reaching `.git`, whose objects git marks read-only. With the
   store gone the delete got further and threw `UnauthorizedAccessException`, which nobody caught:
   thirty green tests went red without a single behaviour changing. `TestTemp.DeleteTree` clears
   the read-only bit and swallows both. No assertion was changed, relaxed or removed.
