## What I FIXED in this audit

1. **Cross-thread read of the mutable agent buffer (real, concurrency, crash-class).** `StartStatusAgent`
   captured its context — `_snap`, `_gates`, `_agent.TakeLast(12)`, `_thinking.Recent(8)` — on the UI
   thread **outside** `_gate`, while producer threads mutate those same buffers under `_gate`
   (`AgentEvent`/`Snapshot`/`GateProgress`). Enumerating `_agent` (a `List`) while a producer `Add`/
   `RemoveRange`s it throws `InvalidOperationException("Collection was modified")` — a live-run crash that
   the green gates never hit because the preview/status path was only ever driven single-threaded in
   tests. **Fix:** moved the whole context capture inside the `lock (_gate)` block, materialising the
   immutable inputs before the off-thread `Task.Run`. `src/Conductor/Ui/LiveDashboard.cs`.
2. **Severity model was render-only — nothing produced a non-`Info` severity (shallow, A14-adjacent).**
   B4.4 shipped the glyph/colour mapping and the `IProgressSink.Log(LogEntry)` capture, but **no caller
   ever emitted `Warn`/`Error`/`Success`/`Waiting`/`Human`**, so in a real run every log line rendered
   grey `Info` — the feature was inert. **Fix:** wired the dashboard's own operator-facing control
   feedback (in-budget, `LiveDashboard.cs`): destructive-action confirmations (ABORT/SKIP/KILL) →
   `Warn`, "press again to confirm" → `Waiting`, injected-instruction success → `Success`, injection
   failure → `Error`, via a new private `Log(string, LogSeverity)` overload. The severity model is now
   actually exercised on the operator's most safety-relevant lines. (Wiring the *orchestrator's* central
   log path is deferred — see FU-B4-1.)
3. **Alt-screen restore could throw out of a signal/exit handler (hardening).** `AltScreen.Leave()` is
   invoked from `PosixSignalRegistration` and `AppDomain.ProcessExit` handlers, where the underlying
   stream may already be torn down; a throwing `_out.Write`/`Flush` there would escape the handler and
   crash *instead of* un-wedging the terminal — the exact failure the class exists to prevent. **Fix:**
   `Leave` now writes best-effort (swallows `IOException`/`ObjectDisposedException` per write) and still
   attempts `LeaveAlt` even if `ShowCursor` fails, so a dying stream can never turn a clean exit into a
   crash. `src/Conductor/Ui/AltScreen.cs`.

## What remains shortcut / weak / assumed / NOT fully fixed this session

- **Severity is not emitted by the orchestrator's central log path.** `Orchestrator` still logs via
  `sink.Log(stamped)` (plain string → `Info`) at `Orchestrator.cs:1241`. The lines an operator most wants
  colour-coded during an unattended run — gate-failed, backoff, needs-human, stage-confirmed — are still
  grey. Classifying those messages and emitting `LogEntry` with the right severity touches `Orchestrator`
  broadly and needs a message→severity mapping decision, so it exceeds this audit's safe UI-scoped budget.
  Deferred → **FU-B4-1**.
- **Alt-screen restore on the *signal / ProcessExit* paths is proven by inspection only.** The
  `AltScreenTests` cover enter/leave/idempotent/redirected via a `StringWriter`, but the
  `PosixSignalRegistration` and `AppDomain.ProcessExit` safety nets are not driven by any test (they need
  a real process/signal). The hardening (#3) makes them fail-safe, but "Ctrl+C leaves a clean prompt" is
  still a manual claim, not a headless assertion. Deferred → **FU-B4-2**.
- **The status-agent probe is fire-and-forget with no CancellationToken.** `StartStatusAgent`'s
  `Task.Run` catches broad `Exception` and surfaces the message into the pane (acceptable per A15 — it is
  *surfaced*, not swallowed), but it is unobserved (`_ =`) and carries no CT, so a hung `StatusAgent.Run`
  leaks the task until process exit and cannot be cancelled by closing the modal. Low risk (single,
  operator-initiated). Deferred → **FU-B4-3**.
- **`_statusLines`/`_modalLines.Count` is read in `HandleModalKey` without `_gate`.** The background probe
  reassigns `_statusLines` under the lock; the UI thread reads `.Count` unlocked. Reference assignment is
  atomic in .NET so this cannot crash or tear, but it is an inconsistency with the rest of the class's
  locking discipline. Noted, not fixed (no defect). Watch it if the modal state grows.
- **Live-token *end-to-end* still depends on FU-B2-1.** The token line is correct given the snapshot, and
  the orchestrator does populate `SessionTokens*` from the live agent — but the persisted-`TokenDelta`
  fold loop (`LiveMetrics` consumer) remains unproven by a recorded run (FU-B2-1, owned by B5). B4's part
  is done; the surrounding metrics loop is not B4's to close.
- **`TrackerParserTests.ParsesRealLoomTracker` was relaxed this phase (`== 35` → `>= 30`).** Reviewed and
  **accepted**: it asserts against a *foreign, live* file (`C:\code\DevContext2-ui\LOOM-START.md`) that a
  separate Loom run mutates, and `src/Conductor/Core/TrackerParser.cs` was **not** touched in this diff —
  so the exact-count coupling was genuinely fragile and the new invariant-based assertion (bulk parses +
  stage grouping + non-empty ids) is the better test, not a cover-up of a regression. Kept as-is; flagged
  here for the trail.

## Risks the next phase (B5 — timeline/replay) should watch

- **Preserve the pure `DashboardState → IRenderable` split.** Every B4 invariant (tree, folding, thinking,
  severity, token line) is unit-tested *through* that split. A timeline pane must extend `DashboardState`
  and add a pure renderer, not reach into the live buffers — and must keep all reads of the mutable
  `_agent`/`_thinking`/`_log` buffers under `_gate` (see fix #1 for the failure mode).
- **Alt-screen + Spectre `Live` is load-bearing.** Any new full-screen view must render inside the
  existing `Live`/alt-screen context (like the modals do) — do not open a second `AnsiConsole.Live` or a
  raw write, or the terminal desyncs / the restore guarantee breaks.
- **Close FU-B2-1 to make the live-token line provable end-to-end** (B5 owns the metrics consumer).
