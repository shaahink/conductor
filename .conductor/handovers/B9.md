## Weak / deferred / not fully covered

- **`CheckpointPlanner` ignores `checkpointId` and `stageNotes`** — the deterministic split-on-separators approach is intentionally simple (the real planner persona refines via MCP). The unused parameters are the `IPlanner` contract surface but a richer decomposition (e.g. using stage notes for context) would need a real LLM call. Deferred to a future planner persona upgrade.
- **`BuildRolloverResumeHint` re-reads the entire `events.jsonl` on every rollover** — acceptable at session boundaries (rollovers are rare, <1000 events expected), but could become a perf concern for plans with 10k+ events. Could be mitigated with an in-memory TaskGraph kept live across sessions. Deferred; not a correctness bug.
- **`McpTaskServer` has no production wiring** (`Orchestrator.cs`) — the journal fold wire-in exists, but the MCP server itself is not yet spawned as a child process that the agent's MCP client connects to. Per the B9.4 QA statement: "McpTaskServer has no production wiring … full wire-in still deferred." This is the largest remaining integration gap — the agent cannot yet call MCP tools at runtime.
- **`task_list` with empty checkpointId returns empty results** — no validation error for missing `checkpointId` argument; behaves as "list all tasks for empty-string checkpoint". Harmless but inconsistent with `task_add`'s validation.
- **No integration tests for orchestrator B9 codepaths** — `CheckSoftBreak`, `FoldMcpJournal`, `BuildRolloverResumeHint`, and `_decomposedCheckpoints` crash-recovery are tested at unit level (SoftBreakTests, TaskGraphTests, PlannerTests) but not via live orchestrator. Consistent with repo's test pattern (unit-only).
- **`TaskGraph` is not thread-safe** — `_tasks` and `_byId` are mutated without locking. Safe under the current single-threaded access pattern (orchestrator loop and single-session MCP server), but B12 parallel lanes or concurrent MCP clients would need a `lock` or immutable snapshot pattern.

## Risks the next phase (B10) should watch

1. **`dependsOn` scheduling** — B10.1 adds a dependency graph between stages. The task graph beneath each checkpoint should inform readiness: a stage isn't truly "done" until all its tasks are complete, not just its checkpoints. The soft-break resume hint needs to work with `dependsOn` ordering (a stage whose upstream hasn't finished subtasks may need deferral).
2. **`McpTaskServer` live integration** — the next phase that enables MCP at runtime must: (a) spawn the MCP server as a child process before the agent starts, (b) configure the agent's MCP client to connect to it, (c) handle the server lifecycle (clean shutdown, crash recovery). The journal-fold pattern is tested and ready; the full wire-in is the gap.
3. **Event log growth** — `BuildRolloverResumeHint` reads the full log. If B10 produces many events per stage, this linear scan at every rollover could become noticeable. Consider adding a `TaskGraph` snapshot cache or only folding task-typed events.
4. **Thread safety for parallel execution** — `TaskGraph`, `_decomposedCheckpoints`, and `_softBreakSignalled` are all unsynchronised instance fields. They're safe under the single-session loop model, but B12.2 (worker pool) will need locking or channel-based designs.
