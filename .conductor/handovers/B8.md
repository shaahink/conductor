## Weak / deferred / not fully covered

- **LessonsManager.Append is not thread-safe** — two concurrent writes would lose an entry. Currently harmless (single-orchestrator model per plan), but B12 parallel lanes would need a `lock` or a single-writer channel. The temp-file-rename pattern provides atomicity per-write but not across concurrent writers.
- **ReadRecent re-reads + re-parses from disk on every call** — both `BatterySection` and `Vars` call `ReadRecent`, resulting in double-read per session. Harmless for a <10KB file but wasteful; could cache with a simple file-write-timestamp check.
- **StageConfig.Kind has no validation** — a typo (e.g. `"reveiw"`) silently falls back to normal delivery behaviour. Worth adding to `CollectErrors()` as a warning.
- **RolledOver is post-hoc (not mid-session cooperative)** — the check fires after `agent.WaitForExitCode()`, so the session still burns tokens up to the process exit. True cooperative soft-break (finish sub-task, hand off, fresh session) awaits B9 task-graph infrastructure. The session result acknowledges this limitation.
- **RecentFailureBattery only reports the single last red session** — does not surface patterns across multiple failures. A richer digester (e.g. "last 3 red sessions had the same gate failing") is deferred to B12 fix-lanes or the review persona.
- **No test covers the orchestrator wiring** (ReflectionStep called after session, ParseAuditFollowups triggered on audit completion, RolledOver path) — the existing 326 tests cover LessonsManager + PromptBattery + PromptBuilder in isolation, but there are no integration-level tests for the orchestrator B8 codepaths. This is consistent with the repo's existing test pattern (unit-only) and would be a large test-harness investment.
