## What THIS audit session FIXED (second audit)

1. **RunDb.Dispose idempotency** (`RunDb.cs:561`): `Dispose()` was not safe for multiple calls — calling it twice would throw ObjectDisposedException from `_conn.Close()`. Added `_disposed` flag with `Interlocked.CompareExchange` so double-dispose is a no-op. This matters because CLI commands that wrap RunDb in `using` + `using` (or the orchestrator disposing during shutdown while a finally block also disposes) would crash.

2. **CLI RunDb construction error handling** (`Commands.cs` — ReportCommand.RunQuery, TaskCommand.Execute, NoteCommand.OpenRunDb): The `new RunDb(path, logger)` constructor opens the connection and calls `EnsureSchema()` which can throw `InvalidOperationException` (schema version too new) or `SqliteException` (corrupted DB). These were previously unhandled in three CLI verbs, crashing the CLI with an unhandled exception dump. All three now wrap construction + usage in a single try-catch that surfaces a clean error message.

3. **TrackerGenerator hardcoded values** (`TrackerGenerator.cs:49-58, 125-133`): Removed the hardcoded "net10.0" framework version and "548 pass (0w/0e)" test count from the "Baseline numbers" section — these were literal placeholders, not derived from any data source. The section now shows only DB-derivable values (checkpoint total + done count). The hardcoded dependency graph (`F0 → F1 → (F2, F3) → F4` etc.) was replaced with plan-derived dependencies from `plan.Stages[].DependsOn`.
