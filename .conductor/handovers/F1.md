## What this audit FIXED

1. **RunDb constructor resource leak** (`src/Conductor/Core/RunDb.cs:29-38`): If schema creation failed inside `EnsureSchema()`, the opened SQLite connection was never closed (object construction aborted before Dispose could run). Wrapped `_conn.Open()` + `EnsureSchema()` in a try-catch that closes/disposes the connection on failure.

2. **RunDb: enable SQLite WAL mode** (`src/Conductor/Core/RunDb.cs:36`): Added `PRAGMA journal_mode=WAL;` after connection open. Without WAL, concurrent `conductor report --query` during an active orchestrator run could hit "database is locked" errors. WAL mode supports concurrent readers + single writer.

3. **TrackerGenerator: dead variable removed** (`src/Conductor/Core/TrackerGenerator.cs:67`): `stageOrder` HashSet was allocated but never used — removed.

4. **TrackerGenerator: null-safe StatusLabel** (`src/Conductor/Core/TrackerGenerator.cs:147`): `status.ToUpperInvariant()` would NPE if status were null (defensive hardening — DB always returns non-null, but the static method should be safe).

5. **TaskCommand: defensive error handling** (`src/Conductor/Commands/Commands.cs:1754-1762`): `db.GetCheckpoints()` now wrapped in try-catch — a corrupted DB won't crash the CLI; it surfaces a clean error message instead.
