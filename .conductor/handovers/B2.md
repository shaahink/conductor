## What is solid and proven (with evidence)

- **The event log is a real spine, emitted additively at every transition.** `Orchestrator` emits
  `RunStarted`/`StageEntered`/`SessionStarted`/`SessionFinished`/`GateFinished`/`CheckpointConfirmed`/
  `StageConfirmed`/`AttentionRequested`/`RunFinished`/`TokenDelta` alongside — never instead of —
  `state.json` writes (additive discipline held; `state.json` is still written everywhere it was).
  Evidence: `docs/baton/evidence/B2.1-gate.txt`; `EventLogTests` (round-trip, ordering, restart-seq,
  torn-tail tolerance).
- **The writer is crash-safe and single-writer by construction.** `EventLog` drains an unbounded
  `Channel` on one dedicated task, flushes the OS buffer after each drained batch, and fsyncs on
  dispose; `ReadAll` tolerates a trailing torn line and share-reads the live write handle (regression
  proven by `EventLogTests.ReadAllSucceedsWhileLiveWriterHoldsTheFile`, a bug a real `--once` smoke
  surfaced — see commit `88db09c`). `ConfigureAwait(false)` is used throughout the drain; the one
  blocking `GetAwaiter().GetResult()` is isolated to `Dispose` at the run boundary and documented.
- **Fold parity is proven, not asserted.** `RunStateProjection.Fold` rebuilds the `RunState` spine and
  `StateProjectionParity.Diff` proves it equals the legacy `state.json` on the event-owned surface for
  **two** fixtures — a real captured smoke run *and* a Loom-shaped stream (audited+confirmed stage +
  still-running deliver). The parity guard is itself guarded (`ParityContractCatchesADivergentProjection`
  proves `Diff` can go red). Evidence: `docs/baton/evidence/B2.2-gate.txt`; `RunStateProjectionTests`.
- **Crash recovery replays the log.** `RecoverFromCrash` keeps the `state.json` path *and* adds an
  event-log path that detects an orphaned `SessionStarted` (no matching `SessionFinished`) even when
  `state.json` missed it, queuing a resume. Proven by `InterruptedSessionIsDetectedFromTruncatedEventStream`
  + `NoInterruptedSessionWhenAllSessionsHaveFinishedEvents`. Evidence: `docs/baton/evidence/B2.3-gate.txt`.
- **The provider switch is really gone.** `Orchestrator` holds one `IAgentProvider` and calls
  `_agentProvider.DetectsUsageLimit(...)`; the per-mode JSON parsing moved verbatim into
  `Opencode`/`Claude`/`GenericText` adapters, selected by `agent.provider` with back-compat inference
  from the legacy `output`. The usage-limit regex is unchanged (behaviour preserved, the stage trap).
  Proven with captured-sample parse tests + factory-selection theory. Evidence:
  `docs/baton/evidence/B2.4-gate.txt`; `AgentProviderTests` (14 cases).
- **Host/DI/Options + structured logging is real.** `ConductorHost.Build` composes the Orchestrator
  through DI, validates `PlanConfig` fail-fast on start via `IValidateOptions` (sharing one
  `CollectErrors` rule set with `PlanConfig.Load`), and routes logs through Serilog with a
  runId/sessionId/stage/gate correlation scope (`BeginCorrelationScope`). A `--dry-run` writes a
  structured log carrying `run=...` and `stage=...`. Evidence: `docs/baton/evidence/B2.5-gate.txt`;
  `HostLoggingTests` (invalid-plan surfaces, DI composes, dry-run log correlation).
- **`catch {}` swallow sites audited (R2.5 / A15 / FU-B0-6 closed).** Every bare `catch {}` in the
  diff now catches a specific exception type and either handles+comments the intent or would rethrow
  anything unexpected — `AgentSession` raw-tee/dispose, `Orchestrator` control/log/lock/report reads,
  `InstructionQueue`, `DocsExtractor`, `StatusAgent`, `LiveDashboard`, `Commands`/`PreviewCommand`.
  No severity was lowered to achieve this.

## What I FIXED in this audit

- **B2.6 silent defect — persisted `TokenDelta` had no `sessionId`, so `LiveMetrics.ForSession` folds
  zero.** `AgentSession` emitted `new TokenDelta { … }` with no `SessionId`, and `EventLog.Emit`
  stamps only `Seq`/`Ts`/`RunId` (by design — it must not clobber a per-event `SessionId`). So on a
  real run every `tokenDelta` line landed with `sessionId` absent, and `LiveMetrics.ForSession`
  (matches on `td.SessionId == sid`) would attribute nothing to any session — the B2.6 deliverable
  was correct only in its unit tests, which set `SessionId` by hand. **Fix:** thread the conductor
  session number into `AgentSession.Start` and stamp it on the emitted `TokenDelta`
  (`AgentSession.cs`; `Orchestrator.cs:269`). **Test:** added
  `EventLogTests.EmitPreservesSessionIdSoLiveMetricsCanFoldPersistedDeltas`, which drives the real
  `AgentSession → EventLog → LiveMetrics.ForSession` on-disk path and asserts non-empty `sessionId`
  survives the round-trip and per-session folding is correct. Value-only: it locks exactly the
  invariant the bug broke. (Run-wide totals were unaffected; only per-session attribution was dead.)

## What remains shortcut / weak / assumed / not fully fixed this session

- **`LiveMetrics` has no production consumer yet.** `ForSession`/`RunWide` are called only from tests;
  the live dashboard still reads `agent.Tokens*` directly (the F-3 fix for the *live* line is that
  direct read, which works). The projection is staged for B5 to consume from the log. My fix means the
  *persisted data is now correct* when B5 wires it — but the end-to-end "dashboard reads live tokens
  from the log" loop is **not** exercised by a real run in B2. Followup FU-B2-1.
- **`FindInterruptedSession` assumes strictly-sequential sessions.** It tracks a single "most recent
  unmatched start" and cannot represent two concurrently-interrupted sessions. That matches
  Conductor's one-session-at-a-time model today, but it is an undocumented invariant that B-stages
  introducing parallel lanes (later tiers) must revisit. Followup FU-B2-2.
- **Event-log recovery of an *orphaned* `SessionStarted` (no matching `SessionRecord` in
  `state.json`) synthesises a `SessionRecord` and queues a resume with whatever `AgentSessionId` the
  event carried — possibly empty.** A resume with an empty agent-session id will start a *fresh* agent
  rather than resume, which is safe-ish (no data loss, a re-deliver) but silently not a true resume.
  This path only triggers on a double-hard crash where `state.json` lost the record; untested against
  a real orphaned-start-with-empty-id stream. Followup FU-B2-3.
- **`RunStateProjection.Fold` covers only the RunState spine.** Timeline / Metrics / Health
  projections are explicitly deferred to B5 (documented in the file). Parity is proven for the spine,
  **not** for `Status`/`AttemptsThisStage`/`Pending*`/etc., which stay `state.json`-authoritative — so
  the cutover to log-as-source (D-5) is *not* done in B2 and must not be assumed. This is by design
  (additive), but it means "event log authoritative-by-parity" from the DoD is only true for the spine.
- **Sync-over-async debt (FU-B0-1 / MA0045) is NOT resolved.** B0 recorded this as B2-owned ("the B2
  async/Host/DI rework"). B2 added the Host/DI/logging but kept the Orchestrator run loop synchronous;
  `MA0045` is still at `suggestion` (not lowered — no ratchet violation, but not raised either). The
  new `EventLog` internals are properly async with `ConfigureAwait(false)`; the *engine* is still sync.
  FU-B0-1, FU-B1-1, FU-B1-2 (CT threading, stdout/stderr split) remain OPEN and re-homed below.

## Risks the next phase should watch

- Do **not** cut over to log-as-source until the non-spine control fields are event-sourced and parity
  is extended to them — today only the spine has parity. Treat `state.json` as authoritative for
  `Status`/`Pending*`/attempts.
- When B5 wires `LiveMetrics` to the dashboard/report, verify against a **real** log (my fix makes the
  data correct, but the consumer path is unproven end-to-end).
- The engine is still synchronous; the async ratchet (MA0045) is a live debt that keeps growing with
  each stage. A dedicated async pass is overdue and should be scheduled explicitly rather than assumed
  "done in B2".
