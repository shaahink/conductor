Both files are reusable workflows. A `workflow_call`-only workflow is never triggered on its
own repository's default branch — it only ever executes inside a caller's run — so "no run on
main" is the correct reading, not a gap. `site-ci.yml` **is** proven green by a real caller:
`shaahink/site-template`'s `ci.yml` line 25 calls `shaahink/.github/.github/workflows/site-ci.yml@main`,
and that caller's latest run on its default branch is 30829094483 = success (see below).
`content-request.yml` was deliberately left un-bumped in N1.3: its safety property is a
credential guard that could not be demonstrated to still hold after a bump, and the strand doc
says an honest skip beats an unproven change.
