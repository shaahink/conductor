## The one honest wrinkle: a pre-existing flake, re-run rather than edited

The **first attempt** at run 30826830593 came back red — but *not* on the version test, which
passed. The failure was:

```
Conductor.Tests.SC4_1SettleAndRetryTests.LiveRun_TheGateBatteryDoesNotStartUntilTheSessionsBgChildHasExited [FAIL]
  the battery only waited 0.6s for a child that had ~4s left to live
  at ...SC4_1SettleAndRetryTests.cs:line 372
Failed!  - Failed: 1, Passed: 1772, Skipped: 0, Total: 1773
```

Why this is a timing flake and not a defect, and not caused by this branch:

- The test spawns a 9-second `Sleeper` **after** waiting for the fake agent to start, then asserts
  the settle waited `>= 2.0s`. On a loaded hosted runner the agent takes longer to exit, so the
  child has already burned most of its 9 seconds before the settle even begins. The "~4s left to
  live" in the message is a static guess in the assertion text, not a measurement.
- Line 366's `Assert.True(child.HasExited)` **passed** in the same run — the settle did not bail
  out early, it simply had less to wait for. The behaviour under test held.
- The identical tree passed on PR run 30826459149 and in the full local battery.
- The previous master run (30765549936, 2026-08-02) failed on the version test **only** — this test
  passed there.

Action taken: `gh run rerun 30826830593 --failed`, which turned the run green. The assertion was
**not** relaxed, the test was **not** skipped, and nothing in that file was touched. The flake is
filed as a tracked conductor bug so it is not lost, and it is out of C1's scope.
