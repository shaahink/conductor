## The one workflow that could not be exercised, and why that is not a fake pass

**sitekit `Release`** triggers only on a `v*` tag push. It has never run on `main` and structurally
cannot, so there is no run of it on the default branch to be green or red — the newest run of it
anywhere is `30645090630` on tag `v0.24.0`, success, on the pre-bump pins.

Its bump is the same two pins as `ci.yml` (`checkout` v5→v7, `setup-node` v5→v7), and `ci.yml`'s
bump is proven green by run `30828800198`. The only way to exercise `release.yml` itself is to cut a
tag, and this workflow publishes to npm via trusted publishing — cutting a throwaway tag would push
a real package version. That is not a price worth paying for a run id, so the bump lands unexercised
and is recorded here as such. The next genuine release is its first run.

This is a stated gap, not a softened measurement: no trigger was widened, no step removed, and
nothing was changed to make an unrunnable workflow look runnable.
