# B1.1 — the site-root links point at the real published URL

## The URL was measured, not assumed

```
https://shaahink.github.io/site/  -> 200
https://shaahink.github.io/site   -> 301
https://shaahink.github.io/       -> 404
```

`astro.config.mjs` sets `site: 'https://shaahink.github.io'` with `base = '/site'`
and the comment "Project page: served under /site/". The repo is named `site`, not
`shaahink.github.io`, so there is no user site at the domain root — hence the 404.
The canonical published URL is `https://shaahink.github.io/site/` (trailing slash;
the bare `/site` form only redirects there).

## What changed

`README.md`, commit `e033f74` on `fix/link-checker-and-node20` in `shaahink/site`:

- line 7, the **Live:** link → `https://shaahink.github.io/site/`
- the deployment step "The site publishes to …" → the same URL

The surrounding setup prose asserted "The repo **must** be named
`shaahink.github.io` (a GitHub user site)" — the same factual error that produced
the dead link — so it now describes the project page it actually is, and names
`astro.config.mjs`'s `base` as the thing that has to move if the repo is renamed.

## What was deliberately NOT changed

The third occurrence of the dead URL is `src/data/site.ts:22`, `site.url`. The
authority doc counted only the two in README; there are three in the run. That one
is **correct as written** and rewriting it would have been the fake fix:
`src/pages/rss.xml.ts:14` builds absolute feed URLs as
`` `${site.url}${withBase(href)}` `` and `withBase` already prepends `/site`.
Pointing `site.url` at `https://shaahink.github.io/site/` would emit
`https://shaahink.github.io/site//site/blog/...` in the RSS feed. It is a
deployment *origin* constant, not a navigable link. It is handled in B1.2 by an
anchored exclusion instead.
