# B1.4 — actions on current majors, PR merged, `main` green

## The bump was driven by a measured warning, not a guess

Run `30765476756` (`Deploy to GitHub Pages`, `main`, before this work) carried:

```
##[warning]Node.js 20 is deprecated. The following actions target Node.js 20 but
are being forced to run on Node.js 24: actions/upload-artifact@v4, pnpm/action-setup@v4
##[warning]Node.js 20 is deprecated. The following actions target Node.js 20 but
are being forced to run on Node.js 24: actions/deploy-pages@v4
```

`actions/upload-artifact@v4` appears in no workflow file here — it is reached
transitively through `actions/upload-pages-artifact@v3`. `checkout@v5` and
`setup-node@v5` were *not* in the warning but were two majors behind.

| action | was | now | current major |
| --- | --- | --- | --- |
| `actions/checkout` | v5 | **v7** | v7.0.1 |
| `pnpm/action-setup` | v4 | **v6** | v6.0.10 |
| `actions/setup-node` | v5 | **v7** | v7.0.0 |
| `actions/upload-pages-artifact` | v3 | **v5** | v5.0.0 |
| `actions/deploy-pages` | v4 | **v5** | v5.0.0 |
| `lycheeverse/lychee-action` | v2 | v2 | v2.9.0 — already current |

Two behaviour changes were absorbed explicitly rather than inherited silently:

- **setup-node v6** narrowed *automatic* package-manager detection to npm. The
  workflow already declared `cache: pnpm` explicitly, so it survives; a comment
  now says why that line cannot be dropped.
- **upload-pages-artifact v4** stopped including dotfiles in the artifact. `dist`
  has none today, but `include-hidden-files: true` is now set so the bump is a
  runtime change and nothing else, rather than a silent content change.

## Merged

PR **[#1](https://github.com/shaahink/site/pull/1)** — "Fix the link checker and
bump workflow actions off Node 20" — rebase-merged into `main`.

Checks were read before merging: `gh pr checks 1` reported **no checks on the
branch**, and `mergeStateStatus` was `CLEAN`. That is correct rather than
suspicious — neither workflow in this repo triggers on `pull_request`
(`deploy.yml` is push-to-main plus dispatch, `links.yml` is weekly cron plus
dispatch), so a PR here cannot have checks. The branch was therefore proven by
dispatched runs instead, before the merge:

- `30820654253` — Check links, branch, **success**, 0 errors
- `30821035704` — Check links, branch, after the bump, **success**
- `30821033251` — Deploy, branch: `build` **success**, all 12 steps

In that last run the `deploy` job failed with **zero steps** and the annotation
"Branch `fix/link-checker-and-node20` is not allowed to deploy to github-pages due
to environment protection rules". The `github-pages` environment has a custom
deployment-branch-policy permitting only `main`, so `deploy-pages@v5` was the one
bump that could not be exercised from a branch — it was rejected before running,
which is a policy refusal and not a fault in the bump.
