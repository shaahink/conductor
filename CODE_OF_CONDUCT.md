# Code of Conduct

## The short version

Be decent. Assume the other person is trying to build something good.

## Scope

This applies to issues, pull requests, commit messages, and any other space where people interact
about this project.

## Expected behaviour

- **Critique the work, not the person.** "This test doesn't prove what it claims" is useful. "You
  don't know what you're doing" is not.
- **Assume good faith.** Most disagreements here are about evidence or trade-offs, not motives.
- **Be specific.** This project runs on evidence — the same standard applies to a review comment as
  to a gate result.
- **Accept a decision once it's made.** Argue your case, then let it go. Reopening a settled ADR
  needs new information, not repetition.

## Unacceptable behaviour

Harassment, personal attacks, discriminatory or sexualised language, deliberate intimidation,
sustained disruption, publishing others' private information, and any conduct a reasonable person
would consider inappropriate in a professional setting.

## Reporting

Do not open a public issue. Contact the maintainer privately — through the contact details on
[@shaahink's GitHub profile](https://github.com/shaahink) — or, if the behaviour breaches GitHub's
own rules, report it directly to GitHub via
[Report abuse](https://github.com/contact/report-abuse).

Reports are handled confidentially, and the reporter is not required to interact with the person
they are reporting.

Security vulnerabilities go somewhere different: see [SECURITY.md](SECURITY.md).

## Enforcement

The maintainer may edit, hide, or delete contributions, and may temporarily or permanently block
anyone from the project. Enforcement is proportionate — a warning first, unless the behaviour is
severe enough that it isn't.
